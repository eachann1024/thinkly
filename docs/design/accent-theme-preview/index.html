02 / 色彩角色

列表边框是锚点，浅底只是浅底。

当前主题 · 对比度

普通文字目标 4.5:1；必要的边界与焦点目标 3:1。原色边框不足时会明确标出，不伪称通过。

浅色取自当前列表真实色值；深色是恢复各主题色的设计候选（叶脉为新增暖橄榄候选），列表仍保留原有圆角、浅底与布局。最终深色值须在真实应用背景上复核。

03 / 完整实施路径

一次覆盖所有消费者，不留“第二期”。

下面是选定方案后的完整工作范围；此页面仅做设计对照，尚未修改真实应用。

  1. 01

    确认视觉方案

    A 实色填充是推荐；B 延续边框；C 保持轻量。以这三个可操作版本选择，也可指定组合。现有列表结构、圆角、密度已确定保留。

  2. 02

    清点真实入口与消费者

    沿主题设置 → 偏好状态 → CSS token → 标签/导航/列表/按钮/选择控件/链接/编辑器检查。区分全局控件、局部样式、动态内联值与第三方组件，逐一映射。

  3. 03

    拆分颜色职责

    定义强调实色、实色前景、强调文字、弱背景、选中边框和焦点环。保留现有 --accent 作为交互弱表面的兼容语义，避免一次全局替换改变菜单与编辑器。

  4. 04

    贯通九主题与明暗模式

    浅色以现有列表边框为真值。深色解除统一灰阶覆盖，恢复所选主题强调色并调整明度；海蓝、鸢尾、松绿、朱砂、莓红、葡萄、叶脉、浅秋、麦笺逐一核对。

  5. 05

    保留状态归属与持久化顺序

    沿用现有主题键、存储及事件顺序，不新增第二套偏好源。核对旧设置、启动恢复、明暗跟随系统、跨窗口同步、设置导入与未知值回退；如需迁移只在原状态所有者处理。

  6. 06

    分组替换交互样式

    选定的顶部/导航表达与列表同色；按钮区分主要/次要动作；开关、单选、链接使用各自语义。hover、pressed、selected、focus-visible、disabled 不混用，成功/警告/错误保持独立。

  7. 07

    处理键盘、对比度与动效

    校验普通文字、实色前景、控件边界和外置焦点环；低对比纸色保留锚点并补足可辨识边界。标签键盘导航、关闭后的焦点恢复、降低动态效果全部涵盖，仅使用 120–180ms 轻过渡。

  8. 08

    最小必要验收与交付

    逐一覆盖 9×明暗色值和受影响状态，再核对主题持久化/跨窗口的相关步骤。按仓库规则不写、不跑测试用例；选择必要类型/构建或交互检查，若触及桌面宿主再安装核验。版本补丁加一，仅提交本任务并推送；涉及 CI 的必要远端步骤实际成功后才宣称通过。

04 / 研究与取舍

保留现有技术，修正颜色语义。

不新增依赖。实现阶段可复用现有 Motion，普通颜色状态使用 CSS；不引入弹跳、流光或持续动画。

为什么推荐 A

最直接消除“浅蓝底被当作强调色”的误解。顶部与导航明确呈现列表边框的真实实色；列表仍然柔和。代价是色彩占比更大，因此保留 B、C 供并排判断。
